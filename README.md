# 群众赛事医疗资源编排服务

赛事安全负责人在批准周末活动前，需要能直接回答：**路跑、青少年球赛、老年健步若同时出现伤情，哪支救护队、哪台除颤设备、哪条转运路线能立即接手**，而不是等现场打电话抢资源。

本服务是一个零外部依赖、可独立运行的编排引擎（Node.js，仅用标准库）。它把主办方、医院、急救站、志愿团队各自维护的保障资料汇成对**点位（post）× 时刻**的确定性编排，并对每一次调整与冲突留痕、可解释。

> 所有内置数据（机构、人员、证照、伤情、PHI）均为虚构演练资料。真实个人健康资料不得写入公开事件流。

## 它保证什么

- **方案生效闸门**：只有引用当时有效规范、布/撤场缓冲达标、排班无冲突，且经 `SAFETY_DIRECTOR` / `MEDICAL_AUTHORITY` 签署的方案才生效；旧规范方案被驳回，须重编重签。
- **即时接手，不抢资源**：任一时刻对任一点位给定伤情，直接给出救护队、AED、车辆、路线、接诊医院与 ETA；车辆是待命池、事件时才锁定，并发伤情不会分到同一辆车/设备。
- **通知只重排受影响岗位**：高温预警、证照到期、设备故障、路线改变，只替换对应点位失效的那个槽位（队伍/AED/路线），其他岗位保持不动。
- **突发抢占有补位、有升级**：突发伤情可调用低风险点位资源，但原岗位**同步**获得补位；补不到则记录 `NO_BACKFILL` 升级给指挥中心。抢占只能取 `LOW` 风险点位。
- **不产生两份任务**：命令按 `command_id` 幂等，通知按 `notice_id` 去重（重复通知只留 `NOTICE_SUPPRESSED`），重复交接被拒绝。
- **PHI 物理隔离**：个人健康资料只进独立 PHI 分区（独立文件、独立读取通道，仅接诊医院可写）；公开赛事视图与运维事件流都不含 PHI、人员证照或车辆编号。

## 目录

| 路径 | 作用 |
| --- | --- |
| `src/domain.js` | 事件/命令/通知/调整类型、冲突码、机构与角色枚举 |
| `src/norms.js` | 版本化规范（虚构 h1/h2）：布撤场缓冲、AED 响应时限（高温收紧）、各活动资质与医院能力 |
| `src/time.js` | 时间窗、重叠、缓冲工具 |
| `src/scheduler.js` | 排班求解器：最短路图、资质/人数/AED 时限/担架/路线开放/医院能力/ETA 匹配，输出冲突解释 |
| `src/resolve.js` | 突发事件响应解析（纯函数，引擎落事件与演练只读推演共用同一逻辑）：接手、抢占、补位 |
| `src/store.js` | 追加事件存储：主分区与 PHI 分区分离、命令/通知幂等、JSONL 持久化 |
| `src/engine.js` | 编排引擎：审批生效、局部重排、抢占补位升级、交接、状态投影 |
| `src/views.js` | 三视图：`drillView`（演练）、`adminView`（冲突与调整链）、`publicView`（脱敏公开） |
| `src/server.js` / `src/cli.js` | 独立 HTTP 服务与命令行入口 |
| `src/runner.js` | 场景批量回放 |
| `data/scenario.json` | 2026-10-10 三活动同发完整演练（含驳回重签、四类通知、三起并发伤情、抢占补位、交接、PHI） |
| `tests/` | 19 项契约/单元/端到端/HTTP 测试 |

## 快速开始

```bash
npm test            # 运行全部测试

# 回放整段周末演练（打印每条命令结果；预期 2 个失败是被正确拒绝的：旧规范方案、重复交接）
npm run replay

# 演练人员：指定时刻 + 点位 + 假设伤情，验证响应者与转运交接（只读推演，不落事件）
node src/cli.js drill data/scenario.json \
  --at 2026-10-10T09:59:00+08:00 --post P_RUN_5K --injury CARDIAC

# 管理端：解释每次调整、抢占补位与升级
npm run admin -- --asOf 2026-10-10T10:25:00+08:00

# 公开赛事视图（核对无 PHI / 无内部调度信息）
node src/cli.js public data/scenario.json --asOf 2026-10-10T10:05:00+08:00

# 启动独立 HTTP 服务
npm run serve            # http://localhost:8080，已载入场景
```

## HTTP 接口

| 方法 & 路径 | 说明 |
| --- | --- |
| `POST /commands` | 单条命令：`declare_resource` / `resource_notice` / `submit_plan` / `approve_plan` / `report_incident` / `complete_handoff` / `record_phi` |
| `POST /replay` | 批量回放命令（演练脚本） |
| `GET /views/drill?at=&post_id=&injury=` | 演练：该时刻该点位对某伤情的响应者与转运交接 |
| `GET /views/admin?asOf=` | 管理端：方案状态、岗位覆盖、调整链、升级、资源占用 |
| `GET /views/public?asOf=` | 公开脱敏赛事视图 |
| `GET /events?asOf=` | 运维事件审计流（不含 PHI） |
| `GET /phi*` | 一律 403：PHI 不由公开编排接口提供 |

伤情枚举：`CARDIAC`（心脏骤停，需 PARAMEDIC + 胸痛医院）、`TRAUMA`、`PEDIATRIC`（需儿科能力）、`SENIOR_FALL`（需担架车 + 担架接诊点）、`HEATSTROKE`。

## 内置演练发生了什么（`data/scenario.json`）

1. 各机构分别声明医院能力、救护车（含一台担架型）、救护队与证照、AED、转运路线与路网耗时。
2. v1 方案引用已过期的 `norm-2026-h1` → 签署时 **NORM_VERSION_MISMATCH 驳回**；按 `norm-2026-h2` 重提 v2 → 安全负责人签署生效，产生初始编排。
3. 09:05 高温橙色预警（滨江）→ 只重排该区域点位，AED 时限收紧到 3 分钟；同一预警重复推送 → `NOTICE_SUPPRESSED`，不产生第二次调整。
4. 09:10 健步起点 AED 故障 → 仅该点位 AED 换备用机，队伍不变。
5. 09:20 10 公里组组长证照到期 → 该组离场，仅该点位换机动 EMT 组，AED 保留。
6. 09:30 滨江路管制 → 5 公里点链路切到环城桥备用线。
7. 10:00 三处同时伤情：
   - 路跑心脏骤停：重症组 + 现场 AED + 备用线送胸痛中心；
   - 青少年球赛创伤：现场只有急救员 → **抢占入口值守（LOW）的 EMT 组**，原岗位由志愿补位组同步补位，记录 `PREEMPTED_WITH_BACKFILL`；
   - 老年跌倒：担架车 + 担架接诊点。
   三起事件的队伍 / AED / 车辆互不重复。
8. 医院完成交接（重复交接被拒），接诊医院把虚构伤情摘要写入 PHI 独立分区；公开视图与 `/events` 均不可见。

## 设计要点

- **事件溯源**：所有决策来自追加日志，状态由投影按序重放得到；可在任意历史时刻 `asOf` 回放与核对。
- **引擎与演练共用 `resolve.js`**：真实 `report_incident` 落事件、演练 `drillView` 只读推演，二者用同一份接手/抢占/补位逻辑，避免“演练能过、实战不一致”。
- **冲突即解释**：求解器在淘汰资源时保留原因（资质、人数、AED 时限、车型、路线封闭、医院能力、接诊窗口、ETA），管理端逐条配中文说明。
- **资源分机构维护**：设备/路线/证照类通知只能由资源 `owner_org` 发出，否则 `OWNER_SCOPE` 拒绝。
